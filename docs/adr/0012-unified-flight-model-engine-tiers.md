# ADR-0012: 统一飞行模型 + 引擎 γ 分级

- 状态: Accepted
- 日期: 2026-08-05
- 决策者: 用户（产品决策）+ 工程评审

## 背景与问题陈述

当前存在**两套相互矛盾的飞行模型**：

1. **Phase 1 `travelDistance`**（`src/engine/physics/lorentz.ts`）：固定速度 → 距离。专注时长 = 船上固有时，`distance = v·γ·τ`。25 分钟 @0.99c 仅 ~0.0003ly（约 21AU），**单次专注无法到达任何恒星**。
2. **S18/S19 逆运算** `requiredFocusMinutes` / `cruisePlan`：目的地 + 时长反推"任意所需 γ"（`RECOMMEND_MAX_GAMMA = 50000`），即速度随需求无限拔高——与固定速度模型在语义上矛盾。

ROADMAP 原引擎分级按 **β**（0.90c → 0.99c → 0.999c → 0.9999c → 跃迁瞬时到达）：按该表，最慢档 0.9999c 到达 1 光年仍需约 5 天固有时，**任何恒星在单次专注内都不可达**。引擎解锁系统落地后，矛盾会显性爆发——"想按时到达某颗星，但引擎速率不够"。

此外"跃迁引擎 = 瞬时到达"与"专注即航行"的产品主题冲突：瞬时到达意味着该次航行没有专注时长。

## 考虑过的方案

### 方案 A: γ 分级引擎 + 单一飞行模型（选定）

- 统一模型：`distance ≈ γ·τ`（τ 为船上固有时），`cruisePlan` / `requiredFocusMinutes` / `travelDistance` 收拢为同一组公式。
- 引擎等级按 **γ_max** 分级：引擎决定"同一次专注能飞多远"，解锁曲线即游戏进程。
- 退役 `RECOMMEND_MAX_GAMMA`；`recommendDestination` 上限 = 当前引擎 γ_max，推荐永远可达。
- 不可达（所需 γ > 当前 γ_max）→ 阻止开始，显示所需 γ、解锁路径（还需累计多少专注）、当前引擎下最短专注。
- **无瞬时跃迁**：跃迁引擎 = 最高 γ 档，仍需要专注时长。

**优点:** 模型自洽、可达性可计算、推荐不落空、解锁有进度感、不破坏专注主题。
**缺点:** 引擎数值需要调；曲速三级/跃迁引擎的 γ_max 超出当前 50ly 目录，在 500ly 扩展（S35）前暂无实际用武之地。

### 方案 B: 保留 β 分级 + 多 session 累积

维持教科书 β 数值（0.90c…0.9999c），接受"到恒星需累计数天/多次专注"（多级跃迁路线）。

**优点:** 数值"物理正确"。
**缺点:** 单次专注几乎不动（0.0003ly 量级），"飞向恒星"的幻想被破坏，游戏感极弱。

### 方案 C: 瞬时跃迁兜底

保留 β 分级，用"跃迁瞬时到达"掩盖不可达问题。

**优点:** 数值物理正确 + 远星可达。
**缺点:** 瞬时到达没有专注时长，违背"专注时长 = 航行里程"的产品主题；变成"跳转地图"而非"航行"。

## 决策

采用**方案 A**：

1. 单一飞行模型 `d = β·γ·τ ≈ γ·τ`（τ = 船上固有时，专注时长）；`cruisePlan` / `requiredFocusMinutes` 基于该模型，`travelDistance` 作为其同构特例。
2. 引擎按 γ_max 分级，初始表（数值可调）：

   | 引擎     | γ_max      | 25 分钟可达 | 解锁条件      |
   | -------- | ---------- | ----------- | ------------- |
   | 常规引擎 | 100,000    | ~4.8 ly     | 默认          |
   | 曲速一级 | 400,000    | ~19 ly      | 累计专注 10h  |
   | 曲速二级 | 1,200,000  | ~57 ly      | 累计专注 50h  |
   | 曲速三级 | 5,000,000  | ~238 ly     | 累计专注 200h |
   | 跃迁引擎 | 20,000,000 | ~951 ly     | 里程碑成就    |

3. 退役 `RECOMMEND_MAX_GAMMA`；`recommendDestination` 上限改为当前引擎 γ_max。
4. 不可达 → 阻止 + 显示升级路径（所需 γ / 解锁哪一级 / 还差多少累计专注 / 当前引擎最短专注）。
5. 无瞬时跃迁；"跃迁任务"模式按当前引擎 γ_max 自动计算所需专注时长。

## 决策依据

1. **线性自洽**：`d = γ·τ`，时长与引擎等级两个旋钮相乘决定可达半径，三种既有函数收拢为一个模型，消除矛盾。
2. **解锁曲线即游戏进程**：低引擎到近星、肝引擎到远星；默认引擎（γ≈100k）25 分钟即可到比邻星，开局不被挡。
3. **可达性有明确 UX 落点**："阻止 + 升级路径"把"不够快"翻译成可执行的下一步，而不是含糊的报错。
4. **主题一致性**：砍掉瞬时跃迁，保证每次航行都有与之对应的专注时长。

## 后果

### 正面影响

- 可达性可计算、可单测（所需 γ / 最短专注 / 单次可达半径为纯函数）。
- `recommendDestination` 只推荐当前引擎可达的星，推荐永不落空。
- 引擎解锁成为长期进度轴，与成就（S32）、船长日志（S30）联动。

### 负面影响

- Phase 1 固定速度语义需迁移：历史 `VoyageRecord` 的距离计算与新模型不同，需兼容或标注（仅影响历史展示）。
- 引擎数值（100k/400k/1.2M/5M/20M）为初始建议，需按用户实际体验调。
- 曲速三级 / 跃迁引擎在当前 50ly 目录下无实际可达目标，需等 500ly 扩展（S35）才发挥价值。

### 风险与缓解措施

| 风险                   | 影响 | 概率 | 缓解措施                                                |
| ---------------------- | ---- | ---- | ------------------------------------------------------- |
| 引擎数值平衡不佳       | 中   | 中   | 引擎表集中配置为 `ENGINE_TIERS`，调数不动逻辑           |
| 双模型迁移破坏既有单测 | 中   | 中   | S22 一次性替换并更新 lorentz 相关测试；历史展示走旧逻辑 |
| "开局不可达"劝退新用户 | 中   | 低   | 默认引擎 γ 足以 25 分钟到近星；推荐始终可达             |
| 可达性判定与 UI 不同步 | 低   | 低   | 可达性 API 放引擎层纯函数，SetupPanel 与推荐共用        |
