# ADR-0009: 单一 Neutral 主题 + 星图弹窗

- 状态: Accepted（部分取代 ADR-0007 的多主题决策）
- 日期: 2026-08-03
- 决策者: 项目负责人（用户）驱动

## 背景与问题陈述

1. **主题与星图冲突**：Nova 原有 4 套主题（深空蓝紫 / 赛博朋克 / 复古胶片 / 极简白）。星图为 WebGL 夜空渲染（天然黑色），在复古/极简白等暖色或亮色主题下，暖色背景 + 黑色星图视觉冲突明显，用户明确反馈「很不搭」。
2. **星图定位**：星图被当作「观星/选目的地」的工具，而非主工作视图。整页切换视图的方式与「专注计时器」主流程割裂。
3. **设目的地缺少确认**：点星后需要明确的确认界面，避免误操作。

## 考虑过的方案

### 方案 A: 保留多主题 + 按主题适配星图

- 为亮色/暖色主题给星图换暗色星星/加深背景，或按主题调整星图配色。
- 缺点：每加一套主题都要额外适配星图，复杂度高；用户已明确希望「删掉 4 套主题」。

### 方案 B: 单一 Neutral 主题（暗色） + 星图整页视图（现状修正）

- 只修背景不改变交互形态。
- 缺点：星图仍作为整页视图与主流程割裂，未解决「设目的地要确认」的诉求。

### 方案 C（选定）: 单一暗色 Neutral 主题 + 星图弹窗 + 确认设目的地

- 删掉 4 套主题，改为一套**暗色中性主题**（近黑灰阶 + 保留金色强调色）。
- 星图从整页视图改为**弹窗**（header「星图」按钮打开），弹窗内标记当前位置（太阳系）。
- 弹窗内点星 → 弹出**确认卡片**（恒星详情 + 「设为目的地」/「取消」）→ 确认后「已设为目的地」→ 「完成」关闭弹窗，回到设置页且目的地已预选。

## 决策

1. **单一暗色 Neutral 主题**：删除 `deep-space / cyberpunk / retro / minimal-light` 4 套主题；`ThemeKey` 收敛为单一字面量 `'neutral'`；CSS Token（deep-50..950 / nebula / star-\* / surface / glass 等）全部保留、值改为暗色灰阶，金色 `--color-star-gold` 为唯一强调色。删除主题切换 UI（`ThemeToggle`）。
2. **星图弹窗**：新增 `StarMapDialog`，header「星图」按钮打开；主 idle 视图恒为设置面板 + 航行日志。弹窗懒加载（three chunk 保持不进主包）。
3. **确认设目的地**：点星弹确认卡片，「设为目的地」/「取消」；确认后「已设为目标 + 完成」关闭弹窗，目的地写入 `useVoyageStore.destStarId`（设置页已 store 驱动，自动预选）。
4. **当前位置标记**：星图以金色标记标出当前位置（当前恒为太阳系）。

## 决策依据

1. **用户体验**：暗色中性主题与黑色星图天然融合，聚焦专注场景；星图弹窗符合「工具」定位，不打断主流程。
2. **极简克制**：单一主题 + 单一强调色契合用户一贯的 Linear/Apple 极简审美（见 HANDOFF 用户偏好）。
3. **降低复杂度**：砍掉主题系统分支后，样式、测试、e2e 都更简单。
4. **工程安全**：`ThemeKey` 保留单一字面量 + 持久化迁移（load 时旧值 coerce 为 `neutral`），既有 IndexedDB 数据无需清库。

## 后果

### 正面影响

- 星图与 App 视觉统一，不再有暖/亮主题下的对比度问题。
- 主流程更聚焦：设置 → 开始专注，星图作为弹窗工具存在。
- 前端样式层大幅简化，后续主题回归可复用 `[data-theme]` 机制。

### 负面影响

- 丢失 4 套主题的品牌差异（用户明确接受）。
- 星图弹窗在移动端为近全屏，仍保留「跟随选中恒星」的信息卡布局以保证可用性。

### 风险与缓解

| 风险                            | 影响 | 概率 | 缓解措施                                                                |
| ------------------------------- | ---- | ---- | ----------------------------------------------------------------------- |
| 既有用户 IndexedDB 存有旧主题值 | 中   | 高   | `useSettingsStore.load()` 迁移：非 `neutral` 一律 coerce 并回写         |
| 弹窗场景下拾取坐标 / e2e 确定性 | 中   | 低   | 复用 S17 的 `__TEST_ONLY__.getStarScreenPosition`，e2e 在弹窗内真实点击 |
