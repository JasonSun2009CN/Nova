# ADR-0015: 响应式布局（大屏横屏双栏 / 窄屏竖屏单栏）

- 状态: Accepted
- 日期: 2026-08-08
- 决策者: 用户（产品决策）+ 工程评审

## 背景与问题陈述

主视图（idle）布局在所有屏幕尺寸上都是**单栏垂直堆叠**：`SetupPanel`（max-w-md 窄列：规划卡 + 音效卡 + 启动按钮）与 `HistoryPanel` 上下排布。在电脑 / iPad 横屏上，整屏内容挤在一根 ~448px 的窄列里，两侧大量留白，组件全部竖向堆叠，观感与手机竖屏无差别。

用户需求：**不同屏幕比例应有不同 UI**——电脑 / iPad 横屏不要竖向排布组件（当前形态），改为并排（横向）；手机 / iPad 竖屏保持竖向堆叠（现状合理）。

## 考虑过的方案

### 方案 A: 纯 Tailwind 响应式断点（选定）

只改容器 class：主视图在 `lg`（≥1024px）断点下切成双栏 grid（`lg:grid-cols-2`），窄屏保持单栏堆叠。`SetupPanel` / `HistoryPanel` 在 `lg` 下 `lg:max-w-none` 填充各自列宽。

**优点:** 零 JS、零运行时开销；Tailwind 断点即文档；改动局部（App + 两个 panel 的容器 class）；不影响 e2e（testID 与可见性语义不变）。
**缺点:** 断点写死在 class 里，未来要按具体设备微调需改 class。

### 方案 B: JS matchMedia + 组件级 layout switch

用一个 hook（如 `useIsWide()`）返回布尔值，组件据此渲染不同 JSX 结构。

**优点:** 可在渲染层做结构性分支（如不同组件树）。
**缺点:** 引入运行时监听 / 重渲染；纯 CSS 能解决的问题不需要 JS；与项目"引擎/UI 纯 CSS 布局"习惯不符。否决。

### 方案 C: 断点定为 `md`（768px）

iPad 竖屏（768–834px）与手机横屏（~844px）会被切成双栏。

**优点:** 让更多屏幕享受双栏。
**缺点:** iPad 竖屏 / 手机横屏空间不足，双栏会挤压规划卡与日志；用户明确要求竖屏保持堆叠。否决。

## 决策

1. **主视图（idle）双栏断点 = `lg`（1024px）**：`SetupPanel`（左）与 `HistoryPanel`（右）在 `lg` 下并排；低于 `lg` 保持现状单栏堆叠。
   - 断点依据：iPad 全系横屏 ≥1024px（mini 1024 / Air 1180 / Pro 1194–1366）→ 双栏；iPad 竖屏 768–834px 与手机竖屏 <768px → 单栏堆叠。
2. **容器实现**：App 主视图包一层 `mx-auto grid w-full max-w-6xl lg:grid-cols-2 lg:gap-10 lg:px-8`；`SetupPanel` / `HistoryPanel` 各自容器追加 `lg:mx-0 lg:max-w-none lg:px-0` 以填充列宽，窄屏（<lg）沿用原 `max-w-md mx-auto px-6` 行为。
3. **范围**：仅主视图（idle 的规划 + 日志）。航行视图（全屏沉浸）、结果视图（居中单卡）、星图 / 船长日志弹窗（已自带响应式宽度）维持现状。
4. **不引入 JS**：纯 Tailwind 断点，无 matchMedia、无 resize 监听。

## 决策依据

1. **空间是硬约束**：iPad 横屏 ≈ 1024px 起，双栏每列 ~520px，规划卡与日志列表均舒适；竖屏 / 手机单栏才能保证 `max-w-md` 卡片与表单可用性。
2. **改动最小、回归面窄**：不改组件结构、不动 testID、不动引擎/存储层，e2e 语义（`toBeVisible`）不受影响。
3. **视觉一致性**：沿用 `glass-card` / 发丝线 / 大留白，双栏与单栏共享同一套 token；`max-w-6xl` 让超宽屏（≥1440px）内容仍居中留白，避免横跨整个屏幕。

## 后果

### 正面影响

- 电脑 / iPad 横屏：规划（左）与航行日志（右）并排，信息密度提升、不再单列堆叠。
- 手机 / iPad 竖屏：布局与现状一致，无回归风险。
- 纯 CSS 实现，无运行时开销，与项目现有 Tailwind 风格一致。

### 负面影响

- 主视图在 `lg`~`xl`（1024–1280px）下双栏较紧凑，个别卡片（如推荐目的地行）可能换行——已用 `flex-wrap` / `truncate` 兜底。
- 双栏下左右内容高度不对称（规划高、日志短）时，短侧下方留空——符合常规 dashboard 形态，暂不追求等高。

### 风险与缓解措施

| 风险             | 影响 | 概率 | 缓解措施                                                          |
| ---------------- | ---- | ---- | ----------------------------------------------------------------- |
| 双栏在窄屏误触发 | 中   | 低   | 断点用 `lg`（1024px），竖屏设备全部 <1024px；e2e 增补双栏断点冒烟 |
| 列内卡片换行难看 | 低   | 中   | 复用现有 `flex-wrap` / `truncate` / `max-w-[38%]` 等兜底样式      |
| 列高不对称观感   | 低   | 中   | 接受常规 dashboard 不对称；后续可加 `lg:sticky` 或独立滚动        |
| 未来按设备细分   | 低   | 低   | Tailwind 断点集中可调，改 class 即可                              |
