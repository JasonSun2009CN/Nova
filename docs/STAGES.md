## 五、规划顺序与关键决策（S21 起）

本节是 Phase 2 收尾 ~ Phase 5 的 **开发顺序与依赖说明**，为第三节编号的配套说明。每项验收标准以 `docs/ROADMAP.md` 对应小节为准。

### 5.1 推荐开发顺序（依赖驱动）

| 顺序 | Stage                                    | 理由                                                                                             |
| ---- | ---------------------------------------- | ------------------------------------------------------------------------------------------------ |
| 1    | **S21** 先关 v0.2                        | Phase 2 功能已闭合（S16~S20），先做 2.3 质量保障与验收走查，确认后再进 Phase 3，避免带债开发。   |
| 2    | **S22 → S23 → S25**                      | 航行视图视觉递进：基础分层星流 → Doppler 色彩 → 跃迁过渡动画；S23 复用 S22 的渲染管线。          |
| 3    | **S24 可与 S22/S23 并行**                | 实时仪表盘是纯 UI + 引擎数据已具备（`cruisePlan` / `VoyageController` tick），不依赖渲染升级。   |
| 4    | **S26 引擎等级**                         | 依赖「累计专注时长」聚合（跨历史记录），与 S29 船长日志共享一个 stats 聚合器，可先建纯函数聚合。 |
| 5    | **S27 白噪音**                           | 独立，仅需新增 `public/` 音频资源；注意浏览器 autoplay 限制（用户手势后启动）。                  |
| 6    | **S28 收 Phase 3**                       | 60fps 自动降级 / γ 数值精度对拍 / 8h 稳定性，验收走查后关闭 v0.3。                               |
| 7    | **Phase 4：S29 → S30 → S31 → S32 → S33** | S30 依赖 S29 统计 + 星图路径记录；S31 依赖历史 + 统计；S33 引入云端账户，建议最后且可推迟。      |
| 8    | **Phase 5：S34/S35 → S36 → S37**         | 数据扩展（S34/S35）独立可先做；S36 打磨、S37 发布准备依赖前面版本稳定。                          |

### 5.2 关键架构决策（开工前需开 ADR）

- **S22 航行视图渲染技术选型（建议 ADR-0011）**：VoyageView 现为 Canvas 2D 星流（`VoyageStarFlow`）。升级到「深度分层星流 + 拖尾 + 光行差畸变」需决定：走 **R3F 复用 renderer**（代码复用最高，但 three ~967KB chunk 当前仅在星图弹窗懒加载，航行启动会引入一次加载）；还是**保持 Canvas 2D 手写**（更轻，但拖尾/畸变/Doppler 实现成本高）。该决策影响首屏与航行启动性能、与 S23 的共用程度。
- **S35 Gaia 百万星**：tier3 单独 KDTree + Points 改 GPU BufferGeometry 批量上屏，遵循 ADR-0006 L5 分块 + Z-order 空间预取；Gaia 为 CC-BY-SA，需在关于页标注数据源。
- **S33 好友雏形**：引入账户/云端，突破「本地优先」现状，需新的数据层 ADR；若延期可先只做「本地生成分享链接」。

### 5.3 与既有实现的衔接（避免重复踩坑）

- **S26 引擎等级** 与 S19/S20 联动：`cruisePlan` / `recommendDestination` 的 maxSpeed 与 γ 上限（`RECOMMEND_MAX_GAMMA=50000`）需随引擎等级提升而放宽。
- **S23 Doppler** 遵循现有 StarField ShaderMaterial 结构新增 uniform；测试走纯函数单测 + Playwright 冒烟（WebGL 仅 chromium，20s 超时）。
- **S29/S30 统计** 从 `HistoryRepository` / `VoyageRecord` 聚合；聚合纯函数放引擎层，UI 图表样式遵循 `docs/UI-UX-DESIGN.md`（单一 Neutral 主题 + 金色强调）。
- **S27 音效** 遵循 PWA 离线：音频资源放 `public/` 参与预缓存；沿用「用户手势后初始化 AudioContext」规避 autoplay 限制。
- **S34/S35 数据扩展**：重新生成数据必须 bump `scripts/build-star-catalog.ts` 的 `SOURCE_VERSION`（HANDOFF 坑 #19），否则旧浏览器永不刷新。
